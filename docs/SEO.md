
# OpenBooks SEO System

SEO is implemented as a system rather than a collection of isolated page titles.

The public acquisition flow is:

~~~text
real business problem
      ↓
useful answer
      ↓
practical tool/resource
      ↓
product solution
      ↓
signup
~~~

## Central source of truth

Public indexable paths are maintained in:

lib/seo/site.ts

This registry feeds the sitemap and provides a controlled list of public routes intended for search discovery.

When adding a new search-facing route:

1. create the page;
2. add page-specific metadata;
3. decide whether it should be indexable;
4. add the path to the central registry if appropriate;
5. add internal links from relevant existing pages;
6. verify canonical behavior;
7. test robots/sitemap behavior.

## Metadata

Reusable metadata is defined in:

lib/seo/metadata.ts

It provides:

- title;
- description;
- canonical URL;
- Open Graph metadata;
- Twitter card metadata.

Page-specific metadata should be used when a route targets a distinct search intent.

## Crawl policy

Crawler policy is implemented in:

app/robots.ts

The public site is crawlable while authenticated/customer data paths are excluded.

The configuration explicitly allows the OpenAI search crawler on the public surface while keeping private paths blocked.

Do not place secrets, customer records or workspace pages into the public SEO surface.

## Sitemap

Generated by:

app/sitemap.ts

The sitemap is derived from the central indexable-path registry.

Do not manually duplicate the route list in multiple unrelated files.

## Public content architecture

OpenBooks currently uses several search-intent layers.

### Answer guides

app/guides/

These target practical business questions such as invoicing, sales, expenses, profit and customer balances.

### Industry guides

app/business-guides/

These adapt bookkeeping workflows to specific Nigerian small-business contexts.

### Tools

app/tools/

These provide immediate utility without requiring an account.

Current tools include invoice generation, receipt generation and profit calculation.

### Commercial pages

These target users already evaluating a product category, such as invoicing, bookkeeping, sales tracking, expense tracking, customer debt tracking and receipt software.

## Internal linking

Every new search page should link to:

- at least one relevant educational page;
- at least one practical tool or resource when appropriate;
- the relevant product/sign-up path;
- adjacent pages in the same cluster.

Do not create orphan SEO pages.

## Structured data

The application uses structured data for organization/site identity and selected software/article pages.

Structured data should describe visible page content accurately.

Do not add fake ratings, fabricated reviews, hidden content or unsupported claims.

## Indexing exclusions

Tokenized public invoice pages are excluded from the search index.

These are customer documents, not marketing content.

Workspace routes and API routes are likewise private.

## Search-quality rules

SEO content should be:

- genuinely useful without requiring signup;
- written for the business problem first;
- specific to the audience and workflow;
- internally consistent with the actual product;
- updated when the product changes.

Do not create pages just to repeat a keyword.

## Measurement loop

Once search analytics are connected, use:

~~~text
impressions
   ↓
promising query/page
   ↓
content or UX improvement
   ↓
stronger internal links
   ↓
re-measure
~~~

Do not treat a target such as 1,000 visits/day as guaranteed traffic. It is a growth objective that must be validated through actual search performance.

## SEO change checklist

When adding a public page:

- identify the target intent;
- write a useful answer before the CTA;
- add appropriate metadata;
- add the canonical route;
- update the indexable path registry when appropriate;
- add internal links;
- verify mobile/page experience;
- verify robots and sitemap;
- keep sensitive/private data out of the page.

For AI/search discovery changes, prefer crawlable, useful, verifiable pages over hidden keyword lists.
